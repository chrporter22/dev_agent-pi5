## What this repo is becoming

A **lightweight Telegram vertical to `~/ai-gateway`** for AI coding work, deployed on a Pi 5.

- Bot: receives commands + dictation via Telegram, queues to Redis.
- Worker: `/build` runs the full git/PR flow (clone → gateway → apply → commit → push → PR). `/chat` runs pure delegation. Bot **never** writes to `main`.
- Gateway: does LLM inference only. No local model. No Ollama.
- Analytics: `core/ml/` runs numpy PCA + statistical drift + rules-based risk (Keras + TFLite dropped). Dashboard reads from Redis via `node-api`.
- Security: every secret in env on a backend service. No keys in any frontend. RLS required if a SQL service is ever added.

| Worker can't reach gateway | DNS / `outbound_net` blocked / `AI_GATEWAY_API_KEY` rejected — `docker logs openclaw-worker` |
| `git push` rejected | `GITHUB_TOKEN` missing `contents:write`, or token not authorized on target repo |
| PR open rejected | Token missing `pull_requests:write`, or branch protection blocks the bot |
| Dashboard blank | `openclaw-ml` hasn't run yet; or `node-api` can't reach Redis (`REDIS_HOST`/`REDIS_PORT`) |
| `/chat` returns nothing | `CHAT_HISTORY_MAX_TURNS=0` would break it; must be ≥ 2 |
| Secret leaked into tracked file | **No API keys in any frontend** rule violated — see `.ai/decisions/security/2026-10-28--...md` |
