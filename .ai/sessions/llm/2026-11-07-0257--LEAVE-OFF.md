**Diagnostic cheat sheet:**

| Symptom | Cause |
|---------|-------|
| `openclaw-bot` logs `Connection reset by peer` in a loop | Placeholder `TELEGRAM_TOKEN`. Telegram 404s every long-poll. Not a network fault — TCP/TLS to the Telegram API succeeds from the container. |
| Bot silent, no error | `ALLOWED_USER` is `0` or the wrong id. |
| `/chat` returns nothing | Worker cannot reach the gateway, or `AI_GATEWAY_API_KEY` rejected. Check `docker logs openclaw-worker`. |
| Dashboard shows zeros | `openclaw-ml` not running, or `ML_DATA_SOURCE=none` set. Check `docker logs openclaw-ml`. |

## Open threads (prioritised, not blocking)

1. **Wire a real ML data source.** `ML_DATA_SOURCE=synthetic` is a placeholder.
   The next decision picks the producer — gateway `ml-service`, the bot's
   `/chat` history stream, or something external — and defines the contract
   between `core/ml` and that producer. Until then the dashboard shows
   illustrative numbers, not production data.
2. **Dashboard chart null guards.** `core/pca-backend/src/components/charts/PCAExplorer.tsx`,
   `VarianceChart.tsx`, and `EigenvalueChart.tsx` call `.map()` on nullable
   arrays with no guard. With the keys now populated the charts render — but
   if any key goes missing again, the chart throws `TypeError` and React 18
   unmounts the whole root. There is no error boundary. Add `?? []` guards plus
   an error boundary around the chart group.
3. **`/api/ml/pca/summary` is missing three fields.** The ML worker writes
   `drift:classification`, `ml:heartbeat`, and `ml:last_run`, but the endpoint
   never fetches them. Result: the DriftCard shows `Unknown` and the
   WorkerCard shows `Offline` even though the worker is healthy. Add the three
   fields to the response.
4. **`pca:history` shape mismatch.** The worker stores bare `number[][]`
   projections; the frontend `HistoryPoint` type expects
   `{projection, drift, risk, timestamp?}`. `HistoryTimeline.tsx` reads
   `item.projection?.length ?? 0` → always 0 → the timeline plots a flat line
   at 0. Fix the writer or the type, not both.
5. **Dead routes `/api/ml/drift` and `/api/ml/risk`.** They work and are
   served, but the frontend never calls them — every card reads from
   `/pca/summary`. Wire them up or delete them.
6. **Dead code `parse_instruction()`** in `core/bot/ai_gateway_client.py`.
   Confirmed zero callers — only the module docstring and
   `core/bot/README.md` mention it. Safe to delete.
7. **Stale README line.** `README.md` still says `Phase 5 CI — pending` in the
   "Out of scope" section, contradicting the roadmap that marks Phase 5
   shipped. One-line doc fix.
8. **Drift thresholds vs high-dim data.** `drift_detector.py` scores
   `(‖centroid‖ + mean(variance)) / 2`. The bands (`0.25`, `0.5`, `0.75`) were
   tuned for an embedding space with small per-dim variance. With 128-dim
   synthetic data the variance term alone puts the score near 0.5–1.0, so the
   dashboard renders `High`/`Critical` almost always. The thresholds and the
   rules-based risk classifier bands are a contract — changing them is a
   decision, not a tweak.
9. **`.ai/index/` unbuilt.** The `repo-index` skill is installed but the index
   is not. The repo has grown since adoption. One build would speed up future
   agent sessions.
10. **Pre-commit secret scan.** Still deferred per
    `.ai/decisions/security/2026-10-28--no-api-keys-in-frontend-rls-in-database.md`.
    The 2026-11-04 manual audit confirmed the tracked tree and full git history
    are clean; a gitleaks/trufflehog hook would keep it that way
    automatically.

- **The dashboard was crashing, not rendering empty.** With `pca:latest = null`
  the chart components threw `TypeError: Cannot read properties of null
  (reading 'map')` and React 18 unmounted the whole root — blank white page,
  not a "no data" state. The synthetic source populates the keys, so the
  charts render now. Open thread #2 is the underlying fragility.
- **`node-api` reads the right Redis keys.** No API change was needed for the
  ML data to flow. The gaps are the three *missing* fields in #3, not wrong
  keys.
- **`redis/users.acl.template` already grants `nodeapi` everything needed**
  (`~pca:* ~drift:* ~risk:* ~model:* ~ml:heartbeat ~ml:last_run`, command set
  `+get +lrange +ping`). No ACL change is required for the dashboard.
- **The bot's polling errors were never a network problem.** TCP and TLS to
  the Telegram API succeed from inside the container. The 404 is the
  placeholder token.
